# Старт команды из трёх человек

Это пакет архитектуры и заданий для Codex, не готовое приложение.

## 1. Один общий bootstrap до параллельной разработки

Назначьте backend-разработчика человеком-интегратором. Он работает в репозитории, созданном организатором. Не создавайте новый основной репозиторий.

Если файлы уже есть — не перезаписывайте их этим пакетом. Сначала человек сопоставляет пути и согласует минимальные отличия. Документы v1 должны быть одинаковыми во всех трёх клонах.

Положите этот пакет в корень проекта: AGENTS.md, docs/, prompts/. Прочитайте и примите общий контракт до запуска трёх задач. Сохраните также оригинал ТЗ организатора, если у команды есть отдельный файл.

Распакуйте career_quest_dataset.zip. Из `case_1/career_quest_dataset/` возьмите только содержимое набора в `data/`: employees.json, events.json, skills.json, activity_history.csv, README.md, README.ru.md, README.kz.md. __MACOSX и .DS_Store не нужны. Сохраняйте набор в разрешённом контуре хакатона, не публикуйте его отдельно.

Из files.zip один раз разместите:
- engine.py и demo.py → backend/recommendation/;
- test_engine.py и make_fixtures.py → tests/ai/;
- README.md → docs/engine_original.md (не поверх корневого README проекта).

AI-разработчик адаптирует импорты/пути существующих тестов под package layout. Исходный движок не заменять новым алгоритмом без доказанной необходимости.

Интегратор создаёт только минимальные общие каталоги/пакеты, общий backend requirements и подключение файла recommendation/requirements-ai.txt, .gitignore и .env.example. Зависимости AI: openai, pydantic; тестовые — pytest. До старта это общий bootstrap, после — правила владения из AGENTS.md.

Человек проверяет diff и делает исходный commit/push. Затем каждый человек в СВОЁМ clone получает этот commit и вручную создаёт свою ветку:
- feat/recommendation-engine — владелец AI;
- feat/backend-core — владелец backend;
- feat/frontend — владелец frontend.

Сессии Codex запускайте после этого. Не передавайте двум сессиям одну изменяемую рабочую папку. Уже запущенные сессии перечитывают AGENTS.md/контракт в новой задаче.

## 2. Что установить и подключить

Общее: Git, доступ к организаторскому repo, Codex с уже установленным Superpowers, локальный workspace с общими файлами. Вложения из ChatGPT сами по себе не являются файлами в workspace Codex — распакуйте их на своих ноутбуках.

AI: Python 3.12; виртуальное окружение; openai, pydantic, pytest; для live-проверки действующий OpenAI API key, доступная модель и API-квота. Ключ вводится человеком в локальное окружение, не в чат/промпт. Для доменных/валидационных unit-тестов сеть и ключ не нужны.

Backend: Python 3.12; fastapi, uvicorn, python-multipart, pydantic, PyJWT, pwdlib[argon2], pytest, httpx. sqlite3 входит в стандартную библиотеку Python: отдельный сервер БД и пакет `pip install sqlite3` не нужны. Docker Desktop либо Docker Engine + Compose; Node 22.12+ нужен только для ручной сборки frontend вне Docker. В контейнере Node используется на этапе сборки.

Frontend: Node.js 22.12+ и npm; React, React DOM, TypeScript, Vite, Tailwind; React Router при необходимости. Тесты: Vitest/Testing Library; браузерный smoke-test. Node-версию выбирайте совместимую с фактически закреплёнными пакетами. Backend URL для локальной разработки; OpenAI key и прямой доступ к SQLite не нужны.

Плагины: новых обязательных нет. SQLite/GitHub MCP не нужен для локальных файлов. Документация OpenAI доступна через официальный сайт; Docs MCP можно использовать, когда он уже настроен, не задерживая старт.

## 3. Переменные окружения

Корневой .env.example создаёт backend. Минимальный согласованный набор:
- OPENAI_API_KEY — пусто в шаблоне, значение только у владельца окружения;
- OPENAI_MODEL — id реально доступной модели с Structured Outputs; проверить пробным запросом;
- JWT_SECRET — случайный локальный секрет, не реальный банковский ключ;
- DATABASE_PATH — путь к SQLite, в контейнере /app/runtime/career_quest.sqlite3;
- DATASET_DIR — путь к исходному набору;
- DEMO_MODE — true для ограниченного демо.

Frontend в dev использует Vite proxy `/api` на `http://127.0.0.1:8000`; в итоговом контейнере тот же origin и относительные `/api`. Никаких OPENAI_API_KEY/JWT_SECRET с префиксом VITE_.

Зафиксировать фактически проверенные версии Python/npm-зависимостей. Не указывать `latest` в сдаваемой инструкции без lockfile.

## 4. Промпты

Каждому — ровно свой файл из prompts/. Внутри повторены общий безопасный режим и интерфейсный контракт; это полноценный промпт, а не ссылка на предыдущее сообщение. Прочитать файл можно прямо из сессии Codex:

«Прочитай prompts/01_AI.md целиком и выполни задание только в моей области. Сначала проверь ветку и файлы. Git не изменяй».

Для других участников — 02_BACKEND.md и 03_FRONTEND.md.

## 5. Контрольные точки

Первые 10–15 минут: один общий bootstrap и согласованный commit. Следующие 45–60 минут параллельно: AI — baseline/фолбэк и тесты; backend — auth, seed, профиль и upload; frontend — экраны на явных mocks.

Затем сразу собрать первый вертикальный сценарий profile → recommendations → complete → profile. Не ждать окончания всей разработки для первого соединения модулей. Подключить HR и импорт жюри, проверить реальные запросы с неизвестными id.

Последние 45–60 минут до 18:00: новые фичи запрещены; чистый запуск, реальные и fallback AI-пути, импорт, права, повтор Complete, README, демонстрационные доступы, итоговый commit в репозитории организатора. Локальные unit-тесты не заменяют live-проверку LLM.

Единственная команда конечного запуска после подготовки .env: `docker compose up --build`. Она ещё должна быть реализована и проверена backend-разработчиком; пакет не содержит готового Dockerfile.
