# Career Quest — правила общей разработки

Работают три человека и три отдельные сессии Codex. Это согласованный MVP, а не приглашение заново выбирать архитектуру. Прочитай `docs/architecture.md`, `docs/contracts.md`, `docs/task.md` и промпт своей роли. Сначала сопоставь их с фактическими файлами.

## Git и рабочая директория
- Один человек — один локальный clone и одна feature-ветка. Разные ветки в одной одновременно используемой рабочей папке НЕ изолируют изменения.
- Только read-only Git: status, diff, log, show, ls-files, rev-parse, branch --show-current.
- Без отдельного прямого разрешения человека не выполнять add, commit, push, pull, fetch, merge, rebase, cherry-pick, stash, reset, clean, checkout, switch, создание/удаление веток, worktree, изменение remote. Никогда не делать force push и не откатывать чужую работу.
- Проверь текущую ветку. Если она не соответствует роли, остановись и попроси человека переключить её.
- Сначала прочитай status/diff. Незакоммиченные изменения не удалять. При пересечении в твоём файле уточнить у человека происхождение изменений.
- Работа только в репозитории организатора. Git-интеграцию, коммиты и push выполняют люди. Подтверждаемый прогресс фиксируется минимум каждый час.

## Владение файлами
- AI, ветка `feat/recommendation-engine`: `backend/recommendation/**`, `tests/ai/**`, `docs/ai.md`.
- Backend, ветка `feat/backend-core`: `backend/**` КРОМЕ `backend/recommendation/**`; `tests/backend/**`; корневые Docker/Compose/ignore-конфиги, `.env.example`, `README.md`, `docs/backend.md`.
- Frontend, ветка `feat/frontend`: `frontend/**`, включая его package.json и lockfile; `docs/frontend.md`.
- `data/**` — исходный набор, только чтение. Не класть данные в frontend/public.
- `docs/contracts.md`, `docs/architecture.md`, `docs/task.md`, `AGENTS.md` после bootstrap заморожены. Изменение — только с явного согласия команды; интегратор вносит согласованное изменение один раз.
- Нужен чужой файл — сообщить путь, причину, минимальный патч. Самому его не менять. Не создавать дубли чужих модулей.
- Нет массового форматирования, переноса каталогов, переписывания работающего движка и несогласованного изменения архитектуры.

## Зависимости и секреты
- AI владеет только `backend/recommendation/requirements-ai.txt`; backend включает его в свои requirements через -r. Frontend владеет только зависимостями внутри frontend.
- Никаких незаявленных облачных сервисов, новых плагинов, регистрации аккаунтов или платных действий без разрешения. Реальный smoke-test OpenAI — по разрешению владельца ключа.
- Ключи API/JWT не печатать, не коммитить, не помещать в браузер, не записывать в тестовые результаты. `.env`, SQLite, токены, node_modules, .venv, кеши и сборки исключаются из Git.
- Использовать только синтетические данные хакатона и разрешённый командный контур; не публиковать архивы в сторонние сервисы.

## Разработка и отчёт
- Для этой согласованной задачи не повторять длинный brainstorming. Дай короткий план своей области и выполняй его маленькими проверяемыми шагами. Superpowers не разрешает обходить эти ограничения или автоматически управлять Git.
- Перед реализацией перечислить планируемые файлы. Писать целевые тесты, запускать их, проверять фактический результат.
- Отдельно сообщать: сделано; проверено (точные команды и результаты); не проверено; блокеры; интеграционный интерфейс.
- Нельзя писать «тесты проходят», «API подключён» или «готово», если соответствующая проверка не запускалась. Mock и fallback всегда явно помечать.
- Последний час до дедлайна — интеграция, исправления, README, проверка чистого запуска. Не добавлять optional-фичи.
