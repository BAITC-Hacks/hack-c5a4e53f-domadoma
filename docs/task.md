# Основание: Career Quest, Halyk Bank / HackAlem AI

Рабочая выдержка из ТЗ, присланного командой в разговоре. Это не новый регламент и не замена оригиналу организатора.

Основной сценарий: сотрудник видит профиль и траекторию, получает 1–3 рекомендованных шага с объяснением, выполняет активность, видит изменение прогресса. HR видит проседающие компетенции, отсутствие подходящего следующего шага и участие по активностям.

Ядро — качество и объяснимость рекомендации, а не интерфейсная обвязка. Геймификация не обязательна.

## Must-have
1. Профиль и карьерная траектория произвольного сотрудника: роль, грейд, навыки, пройденные активности и следующие шаги.
2. AI-рекомендация 1–3 релевантных активностей.
3. Обоснование минимум по трём факторам: грейд, разрывы по навыкам, история участия, требования следующего уровня.
4. Отметка выполнения изменяет прогресс по навыку и траектории.
5. HR-view: частые дефициты навыков, сотрудники без рекомендованного шага, участие в активностях.

Жюри загружает три ранее неизвестных проверочных профиля и историю в формате датасета. Пример ловушки: самый низкий Public Speaking, повторные пропуски похожих активностей, критичный для следующего грейда System Design. Однофакторное правило «минимальный навык» не подходит.

## Данные
employees.json, events.json, skills.json, activity_history.csv. У активности указаны gain и max_level; подробные правила в README набора. Данные синтетические. Реальных персональных данных не использовать. Доступ к исходным файлам и внешняя обработка должны соблюдать ограничения организатора.

## Ограничения
Приватность: данные вовлечённости не видны другим сотрудникам без согласия. Разграничение сотрудник/HR. Понятное объяснение продвижения. Запуск одной командой. Добровольность. Запрещены публичные рейтинги сотрудников, выдача однофакторного правила за AI и механика очков вокруг обязательных процессов. Содержательная обработка данных важнее записанного демо.

Отклик интерфейса до 2 секунд, AI-рекомендация до 10 секунд.
